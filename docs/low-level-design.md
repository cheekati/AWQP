# Low-Level Design

## Folder structure

```text
src/AWQP.Domain
  Common/                  Base entities, roles, enums
  Customers/               Customer aggregate
  Products/                Product, revision, drawing, ECR
  Sales/                   RFQ, quotation, order, approval
  Production/              Work order, operation, machine, schedule
  Quality/                 Inspection, defect, NCR, CAPA, RCA
  CleanRoom/               Area, telemetry, access, compliance
  Inventory/               Warehouse, stock, transactions
  Logistics/               Packaging, shipping inspection, shipment
  Traceability/            Serial, genealogy, events
  Documents/               Managed document and audit entities

src/AWQP.Application
  Common/                  DTOs, interfaces, mapping, validators
  Services/                Use-case orchestration

src/AWQP.Infrastructure
  Identity/                ApplicationUser, refresh tokens, JWT service
  Persistence/             DbContext, repository, unit of work, seed data
  Services/                Barcode and QR adapter

src/AWQP.Api
  Controllers/             REST resources
  Security/                current user, exception middleware, activity audit

src/AWQP.Web
  Controllers/             MVC endpoints
  Views/                   Razor screens
  wwwroot/                 CSS and JavaScript
```

## Entity conventions

- All manufacturing entities inherit `BaseEntity`.
- `Id` is a GUID generated by the application.
- `RowVersion` is configured as SQL Server rowversion for optimistic concurrency.
- Soft delete is modeled with `IsDeleted`.
- `CreatedAt`, `CreatedBy`, `ModifiedAt`, and `ModifiedBy` support auditability.

## Application services

- `CustomerService`: customer listing and creation.
- `ProductService`: product listing and creation with category/material grade projection.
- `WorkOrderService`: creates released work orders and pre-populates the 10 MES operations.
- `DashboardService`: aggregate metrics for production, quality, inventory, clean room, and shipping.
- `TraceabilityService`: serial genealogy and event timeline retrieval.

## Repository and unit of work

`IRepository<TEntity>` exposes query, list, get, add, update, and soft-delete operations. `IUnitOfWork` coordinates one EF Core transaction boundary through `SaveChangesAsync`. The design keeps application services persistence-agnostic while allowing optimized SQL, stored procedures, or service clients to replace repositories later.

## Authentication

`JwtTokenService` authenticates with ASP.NET Identity, issues signed JWT access tokens, persists hashed refresh tokens, and rotates refresh tokens on use. Policies are configured for:

- `Production`
- `Quality`
- `CleanRoom`
- `Warehouse`

## Audit trail

Two audit mechanisms are implemented:

1. `AwqpDbContext.SaveChangesAsync` records entity insert/update/delete old and new values to `erp.AuditLogs`.
2. `UserActivityAuditMiddleware` records authenticated HTTP activity to `erp.UserActivityAudits`.

## Clean-room controls

Clean-room operations are represented by:

- `CleanRoomArea`
- `CleanRoomEnvironmentalReading`
- `CleanRoomAccessLog`
- `EnvironmentalComplianceRecord`

Database procedures and triggers calculate compliance against configured temperature, humidity, and particle-count thresholds.

## Traceability invariant

Every manufactured product can be traced through:

- serial number
- batch number
- lot number
- work order
- manufacturing operations
- machines
- operators
- inspections
- packaging record
- shipment

`TraceabilityEvent` records the event timeline, and `ProductGenealogyLink` records parent-child material/product genealogy.
